# Instagram Carousel

Every carousel is one self-contained HTML file (420×525 slides), generated by a small Node script,
exported to 1080×1350 images, checked, and (optionally) published.

The skill folder is the folder that holds this SKILL.md. Call it `<SKILL>` below and use its real absolute path in commands.

| File | When |
|---|---|
| `brand.json` | Always. Name, handle, audience, colors, fonts, logo |
| `references/content.md` | Always, before writing: the content method, 5 structures, hooks, CTA |
| `references/story-bank.md` | When choosing the personal part. Only true stories. Add new ones the user tells you |
| `references/design.md` | Before building HTML: kit helpers, layouts, RTL rules |
| `references/qa-checklist.md` | After export, before showing final slides |
| `references/publishing.md` | Only if the user wants automatic publishing to Instagram |

## 0. First run (once)
1. **Install dependencies** if `<SKILL>/node_modules` is missing:
   `cd "<SKILL>" && npm install && npx playwright install chromium`
   (Needs Node.js 18+. If `node` is missing, tell the user to install the LTS version from nodejs.org, then restart.)
2. **Onboarding** if `brand.json` has `"configured": false`. Ask these questions, a few at a time, in the user's language:
   - Name, business name, Instagram handle.
   - What you do and for whom (one sentence). Who is the audience, and what is their main pain?
   - The one message you want people to remember about you.
   - How you talk (formal/informal, "אתם"/"את/ה", humor or not).
   - Colors: brand hex codes, or a website URL to take them from, or "pick for me". Dark or light background?
   - Logo file and a profile photo (optional). Copy them into `<SKILL>/assets/` and update the paths.
   - 2–3 true stories from their work (a client case, a moment that changed how they work, something a client said).
     Save them in `references/story-bank.md`.
   Write the answers into `brand.json`, set `"configured": true`, and show a one-paragraph summary.
3. Build the example to check that everything works: run `node "<SKILL>/examples/demo/generate.js"`,
   then export it (step 5). If export works, delete nothing. The demo is a reference.

## 1. Idea → structure (content first)
Read `references/content.md`. For the user's idea:
1. Connect it to `core_message`. If it doesn't connect, say so.
2. Find the personal part in `story-bank.md` or in what the user just wrote. **No true story → ask ONE focused question
   that would produce one.** Never invent stories, clients, quotes or numbers.
3. Pick one of the 5 structures and tell the user: structure + why + which story.
4. Comment keyword: a short word tied to this carousel's topic + what commenters get.
   If the user didn't say, offer 2–3 options. Never promise a giveaway the user didn't confirm exists.

## 2. Script as text, BEFORE building
Write slide by slide (headline + 1–2 lines each) + caption draft. Check the 3 writing rules in content.md.
Rewrite anything that sounds like an ad or like AI. Get an OK or edits. Fixing copy in text is 10× cheaper than in HTML.

## 3. Images (pick one mode)
- **Text only:** fine for the whole carousel; use `bg:'warm'` on the slide with the peak of the pain.
- **Single photo:** the user gives one real photo; it sits behind every slide with a different crop.
  Shrink it first: `node "<SKILL>/scripts/shrink.js" <photo> carousels/<folder>/img/photo.jpg`.
  Use `slide(i, N, inner, { photo:{ src:'img/photo.jpg', pos:'50% 30%', zoom:1.1, text:'top' } })`. The dark shade goes on the side away from the face.
- **Generated illustrations (paid, optional):** `node "<SKILL>/scripts/gen-image.js" carousels/<folder>/img/s1.png "<English scene>" --text top`.
  Needs `OPENAI_API_KEY` in `.env`. **Max 2 new images per carousel**, quality medium, never "test" images.
  Tell the user before generating. Look at each result, then shrink it to 720px JPEG with shrink.js and use `scene('img/s1.jpg')`.

## 4. Build & preview
- Folder per carousel in the user's working folder: `carousels/YYYY-MM-DD-<slug>/`.
- Copy `<SKILL>/examples/demo/generate.js` there, set its `SKILL` constant to the real `<SKILL>` path, and change only
  the slide contents. Everything visual comes from `scripts/kit.js` (helpers in design.md).
- Write the caption to `caption.txt` in the same folder. Run `node generate.js` (never shell heredocs).
- Open `carousel.html` for the user (browser) and ask: **"אילו שקפים צריך לתקן?"** Fix only those slides.

## 5. Export
`node "<SKILL>/scripts/export.js" carousels/<folder>/carousel.html`
→ `slides/slide_N.png` (archive) and `slides/slide_N.jpg` (for Instagram: 4:5, under 8MB). Fix any OVERFLOW warning.

## 6. QA
Go through `references/qa-checklist.md`. **Look at every exported image** (read the PNGs). Fix, re-export.

## 7. Publish
- **Manual (default):** tell the user the folder with the JPGs + the caption to paste. They upload from the phone
  (send the images to themselves via WhatsApp/Drive/AirDrop) or from instagram.com on a computer.
- **Automatic (optional, after setup in `references/publishing.md`):** dry run
  `node "<SKILL>/scripts/publish.js" carousels/<folder>`, show slide count + caption, ask
  **"לפרסם עכשיו באינסטגרם?"**, and only after an explicit yes run it again with `--yes`. Report the permalink.

## Non-negotiables
1. RTL for Hebrew (`direction: rtl` in brand.json). The swipe hint points toward the next slide.
2. Slide 1 is a hook that opens a question. Never the brand name as the headline.
3. One idea per slide, readable in about 2 seconds on a phone. Big, short text; if a slide is crowded, split it.
4. Story, not infographic: specific moments, not concepts. At most one list or card per carousel.
5. Last slide = one comment CTA: `כתבו "<מילה>" בתגובות` + what they get. Same word in the caption.
6. Nothing invented: no fake stats, clients, quotes or results. Unsure → `[לאמת: ...]` and ask.
7. 2–10 slides (Instagram limit). Never pad.
8. Never publish without the user's explicit yes for that specific carousel.
